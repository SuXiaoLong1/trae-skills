# 计划先行执行模式

## 核心原则

**在执行任何实际操作之前，必须先制定计划。** 不允许跳过计划阶段直接动手。

## 工作流程

### 第一步：分析需求

收到用户任务后，先仔细分析：
- 任务的目标是什么？
- 涉及哪些文件、目录、系统资源？
- 有没有前置依赖需要确认？
- 可能的风险点在哪里？

### 第二步：制定计划

将任务拆解为具体可执行的步骤，使用以下格式展示：

```
## 📋 执行计划

**目标**: <一句话描述目标>

**步骤**:
1. [ ] <步骤1描述> — <涉及的文件/命令>
2. [ ] <步骤2描述> — <涉及的文件/命令>
3. [ ] <步骤3描述> — <涉及的文件/命令>

**预计影响**: <会修改/创建哪些文件，会影响哪些系统>
```

### 第三步：展示计划并等待确认

将计划清晰地展示给用户，**必须等待用户确认后才能开始执行**。

如果用户提出修改意见，调整计划后再次确认。

### 第四步：按计划逐步执行

用户确认后，严格按照计划顺序执行：
- 每完成一步，标记为 `[x]`
- 如果某一步失败，停下来分析原因，不要盲目继续
- 如果中途发现计划需要调整，先告知用户并等待确认

### 第五步：总结汇报

所有步骤执行完毕后，汇报结果：

```
## ✅ 执行完成

| 步骤 | 状态 | 说明 |
|------|------|------|
| 1. xxx | ✅ | 顺利完成 |
| 2. xxx | ✅ | 顺利完成 |
| 3. xxx | ⚠️ | 有警告但已完成 |
```

## 不适用场景

以下情况可以跳过计划直接执行：
- 用户明确要求"直接做"、"不用计划"、"快点"
- 单步简单操作（如"帮我读一下这个文件"、"这个命令是什么意思"）
- 纯信息查询，无需修改任何文件

## 示例对话

### 用户请求：
> 帮我在项目里加一个日志模块

### AI 响应（展示计划）：
```
## 📋 执行计划

**目标**: 在项目中添加统一的日志模块

**步骤**:
1. [ ] 检查项目结构，确定放置位置
2. [ ] 创建 src/utils/logger.py
3. [ ] 在现有代码中集成日志调用
4. [ ] 验证日志功能正常工作

**预计影响**: 
- 新建 src/utils/logger.py
- 修改现有文件的 import

确认后我开始执行。
```

### 用户确认后 → AI 逐步执行并更新进度
